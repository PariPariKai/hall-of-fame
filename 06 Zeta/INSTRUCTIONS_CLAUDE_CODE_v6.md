# Инструкции для Claude Code — деплой Hall of Fame v6

## Контекст
Hall of Fame v5 уже задеплоен. Обновляем до v6 — это **рефакторинг безопасности и качества**, без новых визуальных фич:

1. **Фикс парсера CSV** во всех трёх файлах — раньше пустая финальная строка (когда файл заканчивается на `\n`) могла создавать пустую запись в данных. Теперь такие строки корректно игнорируются.
2. **Криптографический рандом в wheel.html** — `Math.random()` заменён на `crypto.getRandomValues()` в функции выбора победителя. Для конфетти оставлен `Math.random()` (визуальщина, не нужен крипто-рандом).
3. **Защита пароля рулетки** — `wheel_access_code` больше не лежит в открытом CSV. Вместо этого в коде хранится SHA-256 хэш пароля, браузер хэширует ввод пользователя и сравнивает. В F12 виден только хэш, по которому пароль не восстановить.

## Что нужно от пользователя

Ничего нового. Все CSV-ссылки остаются прежними, **кроме одной**:
- `CONFIG_CSV_URL` **удаляется из wheel.html** (он там больше не нужен)
- В `tickets.html` `CONFIG_CSV_URL` **остаётся** (нужен для таймера)
- В `index.html` `CONFIG_CSV_URL` отсутствует (его там и не было)

## Что РЕАЛЬНО важно проверить

**Важный момент: миграция Config после Codex.**

После работы Codex'а в листе `Config` **больше нет** строки `wheel_access_code`. Это нормально — теперь хэш живёт в коде. Но в `Config` **остаются** другие ключи:
- `raffle_date` — для таймера
- `raffle_title` — заголовок таймера
- `raffle_active` — флаг включения таймера
- `tickets_banner_url` — баннер фона таймера

`tickets.html` продолжает читать `Config`. `wheel.html` больше не читает `Config` вообще.

## Известные технические детали

- **Фикс parseCSV:** добавлена проверка `row.some(c => c.length > 0)` перед добавлением финальной строки. Если строка состоит только из пустых ячеек — она игнорируется. Это безопасный фикс, который не ломает ни один валидный CSV.
- **crypto.getRandomValues:** работает во всех современных браузерах с 2011 года (IE11+, все Chrome/Firefox/Safari/Edge). Не требует HTTPS, работает локально через `python3 -m http.server`. Используется делитель `0x100000000` (2³²) для равномерного распределения в `[0, 1)`.
- **SHA-256 хэширование:** через стандартное Web Crypto API (`crypto.subtle.digest`). **Важно:** Web Crypto API требует **secure context** — то есть либо HTTPS, либо `localhost`. На GitHub Pages работает (там HTTPS), на локальной проверке через `python3 -m http.server` — тоже работает (localhost считается secure). По обычному `http://` на удалённом сервере — НЕ заработает.
- **Math.random в конфетти:** оставлен намеренно. Криптографический рандом нужен только для решений (выбор победителя), не для визуальной случайности позиций конфетти.

## Если что-то пошло не так

**В wheel.html не пропускает с верным паролем:**
- Открой F12 → Console. Если ошибка `crypto.subtle is undefined` — значит страница открыта по `http://` на удалённом домене (не localhost). На GitHub Pages всё будет ок (там HTTPS).
- Проверь что хэш в файле — те самые 64 символа, без лишних пробелов/кавычек.
- Введи пароль ровно как `PariPariWheel`, регистр важен.

**На главной/билетах не показываются данные:**
- Открой F12 → Network — проверь что запросы к CSV возвращают 200 OK.
- В Console будут логи если CSV не парсится. После v6 пустые финальные строки игнорируются — но если в CSV есть строки с одним непустым ником и без остальных полей, они всё равно обрабатываются нормально (фильтрация по `rank in [epic, legendary, artifact]` или `score > 0` отсеет мусор).

**Кто-то нашёл хэш и пытается подобрать пароль:**
- Технически — это требует брутфорса. `PariPariWheel` восстанавливается за минуты на любом GPU.
- Если когда-нибудь это станет проблемой — поменяй пароль на более длинный (12+ случайных символов), пересчитай хэш по инструкции в шапке wheel.html.
- **Принципиальное напоминание:** это защита уровня "замок от честных людей", не банковской системы. Для серьёзной защиты wheel.html нужен серверный бекенд (Apps Script или Supabase), это уже задача v7+.

# Инструкции для Codex — обновление Google Sheets для Hall of Fame v2

## Контекст
Hall of Fame получает новые фичи: добавляется ранг **Эпическая (epic)**, а также модификатор **Уникальный** для розыгрышей особенных призов (типа RTX3070 или конкретной игры). Из-за этого нужно расширить таблицу.

## Что нужно сделать

### Шаг 1. Добавь две новые колонки в существующий лист `Winners`

После существующих колонок добавь:

| nick | avatar_url | prize | rank | quote | date | **unique** | **prize_image_url** |
|------|-----------|-------|------|-------|------|------------|---------------------|

**Описание новых колонок:**

- `unique` — флажок что это уникальный приз. Допустимые значения: `TRUE`, `FALSE` (или пусто = FALSE). Скрипт также понимает `yes`, `1`, `да`. Используй `TRUE`/`FALSE` для единообразия.
- `prize_image_url` — прямая ссылка на изображение приза (например, рендер видеокарты или обложка игры). Используется только когда `unique = TRUE`. Будет показано на обратной стороне карточки при наведении.

### Шаг 2. Обнови проверку данных в колонке `rank`

Старое правило позволяло только `artifact` и `legendary`. Теперь нужно добавить `epic`.

1. Выдели колонку `rank` (D2:D1000 или соответствующий диапазон)
2. Меню: **Данные → Настроить проверку данных**
3. Удали старое правило, создай новое
4. Критерии: **Список из элементов** → ввести: `epic,legendary,artifact`
5. Действие при некорректных данных: **Отклонить ввод**

### Шаг 3. Настрой проверку данных в колонке `unique`

1. Выдели новую колонку `unique`
2. **Данные → Настроить проверку данных**
3. Критерии: **Список из элементов** → ввести: `TRUE,FALSE`
4. Действие при некорректных данных: **Отклонить ввод**

Это сделает в ячейках выпадающий чекбокс/список — удобно.

### Шаг 4. Проверь публикацию

Убедись, что таблица **всё ещё опубликована** в формате CSV:
- **Файл → Поделиться → Опубликовать в интернете**
- Проверь, что публикация активна и опция "Автоматически публиковать после внесения изменений" включена

После добавления новых колонок Google автоматически добавит их в опубликованный CSV — пересохранять/перенастраивать не нужно. **Ссылка не меняется**.

### Шаг 5. (Опционально) Добавь тестовые данные

Чтобы пользователь мог проверить визуал уникальной карточки, можешь добавить одну тестовую строку:

| nick | avatar_url | prize | rank | quote | date | unique | prize_image_url |
|------|-----------|-------|------|-------|------|--------|-----------------|
| TestUnique | (пусто) | RTX3070 | artifact | Победа века | 2026-04-26 | TRUE | https://images.nvidia.com/aem-dam/Solutions/geforce/ampere/rtx-3070/geforce-rtx-3070-product-gallery-full-screen-3840-1.jpg |

(URL картинки — пример, можно любой другой публично доступный)

## Итоговая структура таблицы

| Колонка | Обязательно? | Тип | Пример |
|---------|--------------|-----|--------|
| nick | да | текст | DragonKnight_99 |
| avatar_url | нет | URL | https://... |
| prize | да | текст | RTX3070 |
| rank | да | `epic` / `legendary` / `artifact` | artifact |
| quote | нет | текст | "Победа века" |
| date | да | YYYY-MM-DD | 2026-04-26 |
| unique | нет | TRUE / FALSE | TRUE |
| prize_image_url | нет (но желательно если unique=TRUE) | URL | https://... |

## Замечания

- Старые записи без колонок `unique` и `prize_image_url` будут работать как раньше (просто показываться обычными карточками своего ранга). Ничего ломать не нужно.
- Регистр в `rank` не важен (`Artifact` и `artifact` одинаково работают), но рекомендую нижний регистр.
- Если в `prize_image_url` ссылка битая — на обратной стороне будет тёмный фон с названием приза. Карточка не сломается.

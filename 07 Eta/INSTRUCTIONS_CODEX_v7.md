# Инструкции для Codex — расширение Google Sheets для Hall of Fame v7

## Контекст

v7 — это **большое функциональное расширение**. К сайту добавляются три новые страницы:
- **Anime** — заказы аниме (с dub/sub, сериями, прогрессом)
- **Movies** — заказы фильмов (с типом: movie/youtube/other и опциональной ссылкой)
- **Series** — заказы сериалов и дорам (с сериями и прогрессом, без dub/sub)

Со стороны Google Sheets нужно **создать три новых листа в существующей мега-таблице** и опубликовать их как CSV.

**Что НЕ меняется:** существующие листы `Winners`, `CurrentPrizes`, `Tickets`, `Config`, `Viewers` остаются как есть. Их структура, данные и CSV-публикации не трогаются.

**Что меняется:** в той же мега-таблице (`1voGKd0Zx09_Io-Wb0F5uag9nKi5pME8LGbsyWwTVWOM`) появляются три новых листа.

---

## Архитектурные решения (для контекста)

Эти решения уже согласованы с пользователем, Codex'у их менять НЕ нужно:

- **Статусы:** `pending` / `watching` / `watched` (одинаковые для всех трёх листов; для фильмов `watching` на практике почти не используется, но колонка единая ради консистентности)
- **Серии:** две отдельные колонки `episodes_total` и `episodes_watched` (сайт сам нарисует "4/12" и прогресс-бар)
- **Фильмы:** структурированы через `title` + опциональный `url` + `type` (movie/youtube/other) — больше никаких "ютуб" в title
- **Сериалы:** **без** поля `format` (dub/sub), потому что для дорам и сериалов это редко актуально
- **Аниме:** **с** полем `format` (dub/sub)
- **Migration:** существующие данные пользователь перенесёт сам вручную позже. Codex создаёт **пустые** листы.
- **Аватарки:** на сайте подтягиваются из существующего `Viewers` по `nick` — никакой `avatar_url` в новых листах не нужен

## Шаг 1. Создать лист `Anime`

В мега-таблице создай новый лист с именем `Anime`. Структура:

| Колонка | Тип | Обязательно | Описание |
|---------|-----|-------------|----------|
| `nick` | text | ✅ | Twitch-ник заказчика. Должен совпадать с ником в `Viewers` для подтягивания аватарки. |
| `title` | text | ✅ | Название аниме |
| `format` | text | ✅ | `dub` или `sub` |
| `episodes_total` | number | ✅ | Сколько всего серий (например, 12) |
| `episodes_watched` | number | ✅ | Сколько уже посмотрели (например, 4). По умолчанию 0. |
| `status` | text | ✅ | `pending` / `watching` / `watched` |
| `date_added` | date | ⛔ опционально | Когда заказали. Формат `YYYY-MM-DD`. |
| `date_completed` | date | ⛔ опционально | Когда досмотрели. Формат `YYYY-MM-DD`. |
| `url` | text | ⛔ опционально | Ссылка на Shikimori/MAL/любую страницу с тайтлом |
| `notes` | text | ⛔ опционально | Любые заметки (например, "хронометраж 8 минут") |

**Точная строка заголовков (первая строка листа):**
```
nick	title	format	episodes_total	episodes_watched	status	date_added	date_completed	url	notes
```

(Это табы между колонками, в реальной таблице — отдельные ячейки A1, B1, C1...)

### Data validation (выпадающие списки) для удобства ввода

Применить ко всем строкам начиная со второй:
- **Колонка `format`** (C): выпадающий список из значений `dub`, `sub`
- **Колонка `status`** (F): выпадающий список из значений `pending`, `watching`, `watched`

### Conditional formatting (визуальная подсветка)

Чтобы в самой таблице было видно состояние строки:
- Строки со `status = watched` — серый фон + зачёркнутый текст
- Строки со `status = watching` — лёгкий жёлтый/золотой фон
- Строки со `status = pending` — без подсветки (или белый фон)

## Шаг 4. Опубликовать каждый лист как CSV

Для каждого из трёх новых листов:

1. Меню `File` → `Share` → `Publish to web`
2. Выбрать конкретный лист (по имени) в первом дропдауне
3. Формат — `Comma-separated values (.csv)`
4. Поставить галочку `Automatically republish when changes are made`
5. Нажать `Publish` → подтвердить
6. Скопировать полученную ссылку

Должно получиться три новых CSV-URL:
- `ANIME_CSV_URL` — публикация листа `Anime`
- `MOVIES_CSV_URL` — публикация листа `Movies`
- `SERIES_CSV_URL` — публикация листа `Series`

**Важно:** в публикации должен быть указан конкретный gid конкретного листа, а не вся таблица. Если ссылка не содержит `gid=...&single=true&output=csv` — значит публикация настроена неправильно, нужно переделать.

## Замечания

- **Не вставляй тестовые/демо-данные** в новые листы. Они должны остаться пустыми (только заголовки). Пользователь сам перенесёт реальные данные из старых отдельных таблиц.
- **Не меняй имена колонок** — они должны совпадать с теми, что захардкожены в HTML-парсерах. Регистр важен: всё **lowercase**, разделитель — **underscore** (`episodes_total`, не `EpisodesTotal` и не `episodes-total`).
- **Не объединяй ячейки** в заголовках или данных — это сломает парсинг CSV.
- **Не добавляй формулы** в колонки `episodes_watched` или `status` — там должны быть прямые значения, которые редактируются пользователем вручную. Прогресс-бары на сайте вычисляются на стороне фронта.
- **Никнеймы должны точно совпадать** с `nick` в листе `Viewers` (с учётом регистра) — иначе аватарка не подтянется. Сайт не сломается, просто покажет дефолтную аватарку-плейсхолдер.
- **Если потом захочется добавить ещё одну колонку** (например, `rating` или `season`) — лучше отдельной задачей v8+, чтобы синхронно обновить и парсер на сайте.

# Инструкции для Claude Code — деплой Hall of Fame v7

## Контекст

v7 — это **большое функциональное расширение сайта**. Добавляются:
- **Три новые HTML-страницы:** `anime.html`, `movies.html`, `series.html`
- **Общее верхнее меню** на всех страницах: Hall of Fame · Билеты · Аниме · Фильмы · Сериалы

Цель страниц — показать на стриме красивый список заказов аниме/фильмов/сериалов и дать зрителям возможность быстро искать "это уже смотрели или ещё нет?".

**Что НЕ меняется:** бизнес-логика существующих страниц (`index.html`, `tickets.html`, `wheel.html`) остаётся ровно как в v6. Меняется только добавление общего nav-меню сверху.

**Зависимость:** перед началом работы Codex должен был создать в мега-таблице три новых листа (`Anime`, `Movies`, `Series`) и опубликовать их как CSV. Пользователь передаст три новых URL'а:
- `ANIME_CSV_URL`
- `MOVIES_CSV_URL`
- `SERIES_CSV_URL`

Если пользователь их **не передал** — НЕ продолжай. Запроси у пользователя эти три URL'а в явном виде.

## Архитектурные решения (для контекста)

Эти решения уже согласованы с пользователем:

- **Статусы:** `pending` / `watching` / `watched` (везде)
- **Прогресс серий:** `episodes_total` + `episodes_watched` — сайт сам считает процент и рисует прогресс-бар
- **Аниме vs Сериалы:** у аниме есть `format` (dub/sub), у сериалов — нет
- **Фильмы:** `type` = `movie` / `youtube` / `other`, `url` опционален
- **Аватарки:** подтягиваются из существующего `Viewers` по `nick` — точно так же, как в `index.html` и `tickets.html`
- **Стек:** plain HTML/CSS/JS, без фреймворков, без сборки — продолжаем эту же традицию
- **parseCSV:** копируем точно ту же версию, что в v6 (с фиксом пустых финальных строк)

## Общее меню (nav) — спецификация

Меню должно быть **одинаковым на всех 5 страницах**. Это короткий горизонтальный блок сверху, перед основным контентом каждой страницы.

### Структура HTML

```html
<nav class="site-nav">
  <div class="site-nav__inner">
    <a class="site-nav__brand" href="index.html">ParipariKai</a>
    <ul class="site-nav__links">
      <li><a href="index.html" data-page="hall">Hall of Fame</a></li>
      <li><a href="tickets.html" data-page="tickets">Билеты</a></li>
      <li><a href="anime.html" data-page="anime">Аниме</a></li>
      <li><a href="movies.html" data-page="movies">Фильмы</a></li>
      <li><a href="series.html" data-page="series">Сериалы</a></li>
    </ul>
  </div>
</nav>
```

На каждой странице соответствующий `<a>` помечается классом `is-active`. То есть в `index.html`:
```html
<li><a href="index.html" class="is-active" data-page="hall">Hall of Fame</a></li>
```

На `tickets.html` — `is-active` на `tickets`, и так далее.

### Стилизация (вписать в общий `<style>` каждой страницы или вынести в `nav.css`)

Дизайн в той же эстетике, что и существующие страницы (`#0a0e1a` фон, `#FAC775` золотой акцент):

- **Фон nav:** полупрозрачная тёмная плашка `rgba(20, 25, 40, 0.85)` с лёгким backdrop-filter blur
- **Позиция:** `sticky; top: 0; z-index: 100;` — чтобы прилипало при скролле
- **Padding:** `12px 24px` на десктопе, `10px 16px` на мобильном
- **Brand слева** — мелкий текст с `letter-spacing: 3px`, цвет `#FAC775`
- **Links справа** — горизонтальный список с `gap: 24px`. Каждая ссылка:
  - Цвет по умолчанию: `rgba(255,255,255,0.7)`
  - Hover: `#FAC775`, плавный transition 200ms
  - **Active state (`.is-active`):** золотой цвет `#FAC775` + тонкая подложка снизу (border-bottom: 2px solid `#FAC775` или мягкий glow `text-shadow: 0 0 8px rgba(250,199,117,0.5)`)
- **Мобильный режим (< 640px):**
  - Brand можно сделать ещё короче (например, "PK" или иконкой), или скрыть и оставить только links
  - Links wrap во вторую строку, либо горизонтальный скролл — на твоё усмотрение, главное чтобы все 5 пунктов оставались доступны без необходимости в гамбургер-меню (его делать ещё рано)

**Принципиально:** меню не должно "ломать" существующий look страниц. Существующий title-блок и подзаголовок остаются прямо под меню.

### На `wheel.html` — нюанс

`wheel.html` имеет gate с паролем перед основным контентом. Решение: **меню показывать всегда**, даже до ввода пароля. Меню — это просто навигация между страницами, оно не раскрывает контент рулетки. Пользователь со страницы рулетки спокойно может уйти на другую страницу не вводя пароль.

## Страница 1 — `anime.html`

### CSV-данные
- `ANIME_CSV_URL` — заказы аниме
- `VIEWERS_CSV_URL` — для аватарок (тот же, что в `index.html`)

### Колонки данных в CSV
`nick, title, format, episodes_total, episodes_watched, status, date_added, date_completed, url, notes`

### Структура страницы

1. **Top nav** (общее меню, см. выше)
2. **Header**:
   - Заголовок: "Заказы аниме" (стиль как у `.title` в index.html — золотой, letter-spacing 4px)
   - Подзаголовок-счётчик: "X из Y просмотрено" (где X — количество строк со `status = watched`, Y — общее количество строк)
3. **Controls panel** (sticky под nav или просто фиксированно перед списком):
   - Поле поиска (placeholder: "Поиск по названию...") — ищет подстроку в `title`, case-insensitive
   - Группа кнопок-фильтров статуса: `Все` · `В очереди` (pending) · `Смотрим` (watching) · `Просмотрено` (watched). Активная кнопка подсвечивается золотым.
   - (Опционально, если поместится) — выпадающий фильтр по заказчику (список ников)
4. **Список карточек** (grid или вертикальный список) — каждая карточка одно аниме:
   - **Слева:** аватарка заказчика (40-48px, круглая, fallback — буква никнейма на цветном фоне)
   - **Справа сверху:** ник заказчика (мелким текстом)
   - **Центр:** title крупно. Если `url` есть — title кликабельный (открывает в новой вкладке)
   - **Бейджи в одну строку под title:**
     - `format` — бейдж "DUB" (синий) или "SUB" (фиолетовый)
     - `status` — бейдж "В очереди" (серый) / "Смотрим" (золотой) / "Просмотрено" (зелёный)
     - Если `date_completed` есть — дата маленьким текстом
   - **Прогресс-бар:**
     - Подпись: `{episodes_watched} / {episodes_total}` (например, "4 / 12")
     - Сама полоска: ширина заполнения = `episodes_watched / episodes_total * 100%`
     - Цвет заполнения зависит от статуса:
       - watched (полный): зелёный
       - watching (частичный): золотой
       - pending (0%): пустой
   - **`notes` под прогресс-баром** — серым курсивом, если есть
   - **Watched-карточки визуально приглушены:** opacity 0.6, title с лёгким зачёркиванием — чтобы взгляд сразу выделял "ещё не смотрели"

### Логика сортировки

Дефолтный порядок:
1. Сначала `watching` (то, что сейчас смотрим — самое актуальное)
2. Потом `pending` (очередь)
3. Потом `watched` (история)

Внутри каждой группы — по `date_added` desc (новые сверху), а если даты пустые — в порядке появления в CSV.

### Поведение фильтров и поиска

- Поиск + фильтр статуса работают одновременно (AND)
- Если ничего не нашлось — показать тихую заглушку "Ничего не найдено по запросу '...'"
- Счётчик "X из Y просмотрено" в header **не меняется** от фильтров — он показывает глобальную статистику. Под controls'ами можно дополнительно показать "Показано: N карточек" если хочется.

## Технические требования (общие для трёх новых страниц)

### parseCSV

**Скопируй ровно ту же функцию `parseCSV`, что используется в `index.html` v6** (с фиксом проверки пустых финальных строк). Не пиши свою, не упрощай — используй проверенную.

### Загрузка данных

Паттерн как в `index.html`:
1. `Promise.all([fetch(MAIN_CSV), fetch(VIEWERS_CSV)])` 
2. Парсим оба CSV
3. Строим `viewersMap` (lookup по lowercase nick → `{nick, avatar}`)
4. Применяем `viewersMap` к основным данным — добавляем `avatar` к каждой строке
5. Рендерим

### Обработка отсутствующих/некорректных данных

- Если `episodes_total` пустой/0 — не показывать прогресс-бар вообще (просто скрыть блок), но сама карточка остаётся
- Если `episodes_watched > episodes_total` — clamp до `episodes_total` для отображения прогресса (но показать число как есть)
- Если `status` неизвестный (не входит в `pending`/`watching`/`watched`) — считать `pending` и не падать
- Если `nick` не найден в `Viewers` — показать дефолтную аватарку (буква никнейма на цветном фоне, цвет можно вывести из хэша никнейма)
- Если CSV пустой (нет ни одной строки данных) — показать "Пока ни одного заказа" вместо списка
- Если CSV не загрузился (сетевая ошибка) — показать "Не удалось загрузить данные. Попробуйте обновить страницу." и кнопку "Обновить"

### Стилизация

- Используй **те же CSS-переменные и цветовую палитру**, что в `index.html`:
  - Фон: `#0a0e1a` с градиентами
  - Золотой акцент: `#FAC775`
  - Фиолетовый: `#7F77DD`
  - Белый текст: `#fff` с разной opacity
- Скругления: 8-12px
- Карточки: фон `rgba(255,255,255,0.04)`, border `rgba(255,255,255,0.08)`, hover — лёгкий подъём `transform: translateY(-2px)` и border `rgba(250,199,117,0.3)`

### Адаптивность

Минимум: страницы не должны ломаться на мобильных (< 480px). Карточки на мобильном — одна колонка во всю ширину. На десктопе — 1-2 колонки шириной 600-800px по центру (как у `index.html` через `.wrap { max-width: 1400px }`).

## Известные нюансы и потенциальные проблемы

- **Time-to-first-render** на новых страницах будет ~200-500мс из-за двух параллельных fetch'ей. Это норм. Если показывать "Загружаю..." как в `index.html` — UX будет идентичный.
- **Кэширование Google Sheets публикаций**: Google кэширует CSV-публикации **до 5 минут**. Если пользователь обновил строку в Sheets — на сайте появится не сразу. Это известное ограничение, не баг. Можно добавить `&t={Date.now()}` к URL для cache-busting, но это уже опционально и не на этой версии.
- **Большие CSV (~1000+ строк):** парсинг и рендер всего за раз. Если в будущем заказов станет очень много — потребуется виртуализация списка. Пока не нужно.
- **Аватарки `Viewers`:** если в `Viewers` строка есть, но `avatar_url` пустой — будет fallback с буквой. Это нормально.

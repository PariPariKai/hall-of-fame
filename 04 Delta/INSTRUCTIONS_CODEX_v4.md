# Инструкции для Codex — обновление Google Sheets для Hall of Fame v4

## Контекст
В Hall of Fame добавляется:
1. **Билетная система** — зрители копят серебряные/золотые билеты, разыгрываются на колесе
2. **Управление каруселью** — возможность скрыть конкретные баннеры не удаляя строку
3. **Общие настройки** — дата розыгрыша, код доступа к колесу

Для этого нужно:
- Добавить колонку `active` в существующий лист `CurrentPrizes`
- Создать новый лист `Tickets`
- Создать новый лист `Config`
- Опубликовать оба новых листа как CSV

---

## Шаг 1. Добавить колонку `active` в `CurrentPrizes`

Открой существующий лист `CurrentPrizes`. После существующих колонок добавь:

| image_url | title | link | **active** |
|-----------|-------|------|------------|

**Описание:**
- `active` — TRUE/FALSE. Если TRUE (или пусто) — баннер показывается на главной странице. Если FALSE — скрывается, но строка не удаляется. Удобно подготовить баннер заранее и включить когда нужно.

Настрой проверку данных для колонки `active`:
- **Данные → Настроить проверку данных**
- Критерии: **Список из элементов** → `TRUE,FALSE`
- Действие при некорректных данных: **Отклонить ввод**

Для существующих строк, которые сейчас показываются — поставь `TRUE` или оставь пустым. Скрипт обратно-совместим: если колонки `active` нет вообще или ячейка пуста, баннер считается активным.

CSV-ссылка на `CurrentPrizes` **не меняется** после добавления колонки.

## Шаг 2. Создать лист `Tickets`

Добавь новый лист в той же таблице. Назови `Tickets`.

Структура колонок:

| nick | avatar_url | silver | gold |
|------|-----------|--------|------|

**Описание:**
- `nick` — никнейм участника (обязательно)
- `avatar_url` — ссылка на аватарку Twitch (опционально, без неё показываются инициалы)
- `silver` — количество серебряных билетов (число, по умолчанию 0)
- `gold` — количество золотых билетов (число, по умолчанию 0)

**Логика подсчёта** (для информации, реализована в коде):
- В колесе вес участника = `silver + gold * 5`
- На странице билетов рейтинг считается по тому же весу

**Настрой проверку данных:**
- Колонки `silver` и `gold` — числовое значение, минимум 0
- **Данные → Настроить проверку данных** → Критерии: **Число → больше или равно 0**

**Добавь несколько тестовых строк:**

| nick | avatar_url | silver | gold |
|------|-----------|--------|------|
| TestUser1 | | 25 | 3 |
| TestUser2 | | 12 | 0 |
| TestUser3 | | 50 | 8 |

## Шаг 3. Создать лист `Config`

Добавь новый лист `Config` в той же таблице. Это лист настроек в формате ключ-значение.

Структура:

| key | value |
|-----|-------|

Заполни следующими строками:

| key | value |
|-----|-------|
| raffle_date | 2026-06-01 19:00 |
| raffle_title | До розыгрыша Subnautica 2 |
| raffle_active | TRUE |
| wheel_access_code | (пользователь укажет сам — придумает пароль) |

**Описание:**
- `raffle_date` — дата и время розыгрыша в формате `YYYY-MM-DD HH:MM`. Местное время браузера зрителя.
- `raffle_title` — текст над таймером (например "До розыгрыша Subnautica 2")
- `raffle_active` — TRUE/FALSE. Если FALSE — таймер не показывается на странице билетов
- `wheel_access_code` — секретный код для входа на страницу колеса. Нужно ПРИДУМАТЬ свой и сообщить пользователю. Минимум 6 символов, лучше с цифрами и буквами.

**Важно:** установи права на лист `Config`:
- Лист `Config` тоже опубликуется как CSV, и `wheel_access_code` теоретически можно найти через DevTools на странице колеса. Это нормально — это не серьёзный security, а просто барьер от случайных посетителей. Просто пользователь должен знать, что код не нужно делать как у банка.

## Шаг 4. Опубликовать новые листы как CSV (КРИТИЧНО!)

Каждый лист нужно опубликовать отдельно, как уже сделано с `Winners` и `CurrentPrizes`.

### Публикация листа `Tickets`:
1. **Файл → Поделиться → Опубликовать в интернете**
2. В диалоге раскрой **«Опубликованный контент и настройки»**
3. В первом дропдауне выбери лист **`Tickets`**
4. Во втором — **CSV**
5. Убедись что включена опция "Автоматически публиковать при изменениях"
6. **Опубликовать** → подтвердить
7. Скопируй полученную ссылку — это `TICKETS_CSV_URL`

### Публикация листа `Config`:
Точно так же, но в первом дропдауне выбери лист **`Config`**.
- Получишь `CONFIG_CSV_URL`

Обе ссылки будут вида `https://docs.google.com/spreadsheets/d/e/2PACX-XXX/pub?gid=ДРУГОЙ_НОМЕР&single=true&output=csv` — `gid` у каждой будет разный.

## Замечания

- **Все ссылки на CSV остаются стабильными** — добавление колонок в существующие листы не меняет ссылку. Только при создании новых листов нужны новые публикации.
- **Если хочешь добавить новые поля в Config в будущем** — просто новую строку с ключом. Никаких обновлений ссылок не нужно.
- **Безопасность кода колеса:** код хранится в публикованной CSV, теоретически любой может его найти. Это не блокировка от хакеров, а просто отсечка случайных посетителей. Этого достаточно для целей стрима.
- **Тестовые билеты:** обязательно добавь 3-4 тестовых юзера в `Tickets` с разными цифрами, чтобы было что показывать на странице билетов и в колесе при тесте.
